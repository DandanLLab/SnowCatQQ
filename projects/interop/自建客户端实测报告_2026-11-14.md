## 四、跑通项明细（=自建客户端模式可行）

1. **模块系统**：`snowcat-onebot` 全链 TS 源码纯 ESM 直跑（tsx + 自研 esm-hooks.mjs 做别名解析），无需打包器。
2. **装配链真跑**：`NapCatOneBot11Adapter` 构造 → configLoader（typebox 校验）→ ActionMap 全动作注册 → networkManager 注册三适配器 → openAllAdapters → listener 注册 → 启动报告，一气呵成。
3. **网络层真监听**：三个端口真 bind（13000/13001/13100），Express + ws + 自研 SSE 三种传输全在生产代码路径上。
4. **协议桥真翻译**：OB12 的 meta.connect/heartbeat/get_latest_events、Milky 的响应外壳/版本协商/错误码（404/401/-400）全部走真桥。
5. **鉴权真工作**：Milky authorize（Bearer/query 双路）与 OB12 ws authorize 生产实现原样生效。
6. **启动链上 QQ API 的边界清晰**：InitOneBot 只在两处触 QQ API（getUserDetailInfo 取昵称、registerParseGroupReactEventByCore），独立模式下用可完成桩替身，行为可见可控。

## 五、缺口项与解耦改造清单（InitOneBot 与登录态解耦的具体改法）

### 5.1 InitOneBot 与登录态解耦（核心改造，动 packages/snowcat-onebot/index.ts）

现状：`InitOneBot()` 把「网络层装配」和「QQ 登录态消费」混在一个函数里：

```ts
async InitOneBot () {
  const selfInfo = this.core.selfInfo;
  // ← 登录态消费：getUserDetailInfo 取昵称 + WebUI token 私信推送 + 登录回调
  this.core.apis.UserApi.getUserDetailInfo(...).then(...)
  // ← 中段：网络层装配（与登录态无关，独立模式这部分已实测跑通）
  for (const key of ob11Config.network.httpServers) { ... }
  await this.networkManager.openAllAdapters();
  // ← 尾段：内核 listener 注册（session.getMsgService() 等，登录态产物）
  this.initMsgListener(); this.initBuddyListener(); this.initGroupListener();
  ...
}
```

具体改法（三段式拆分，向后兼容）：

```ts
// 拆成三个阶段函数，InitOneBot 保持为兼容入口按序调用：
async InitOneBotNetwork () {
  // 原中段整体搬入：网络适配器注册 + openAllAdapters + WebUiDataRuntime 注册
  // （WebUiDataRuntime.setQQVersion 需容错：basicInfoWrapper 缺省时跳过）
}
async InitOneBotProfile () {
  // 原首段搬入：getUserDetailInfo / WebUI token 推送 / 登录回调
  // 独立模式不调用；真机模式由登录成功回调调用
}
async InitOneBotListeners () {
  // 原尾段搬入：三个内核 listener 注册（依赖 context.session）
  // 独立模式不调用；真机模式登录后调用
}
async InitOneBot () {
  await this.InitOneBotProfile();      // 真机路径不变
  await this.InitOneBotNetwork();
  await this.InitOneBotListeners();
}
```

配套小修：
- `WebUiDataRuntime.setQQVersion(this.core.context.basicInfoWrapper.getFullQQVersion())` 加存在性判断（独立模式 basicInfoWrapper 可缺省）。
- `registerParseGroupReactEventByCore` 失败已有 catch，日志降噪即可（独立模式预期报错）。

### 5.2 事件注入入口（B 路线真号接活用）

现状：消息事件只能从 `context.session.getMsgService()` 的内核 listener 进来（登录态产物）。
改法：给 `NapCatOneBot11Adapter` 加一个公开的 `injectRawMessage(msg: RawMessage)` 入口（内部即现有 `emitMsg`），让任何壳（QQ 壳 / Lagrange 适配壳 / 测试桩）都能喂数据。改动小（一个 public 方法转发），价值大（壳彻底可插拔）。

### 5.3 selfInfo 的来源解耦

现状：`core.selfInfo` 由真机登录流程填充。独立模式本轮用 mock 值注入。
改法：standalone 入口支持 `--uin/--nick` 参数注入（已实现）；长期可在 core 层提供 `setSelfInfo()` 正规入口。

### 5.4 纯 ESM 兼容三连修（本轮顺手修掉，已进本 PR）

这三处不是独立模式专属问题，是纯 ESM 环境共性坑（打包器容忍、tsx/vitest 炸）：
1. `plugin-manger.ts` 纯类型重导出改 `export type`（HttpMethod/MemoryFileGenerator 等九个）；
2. `StreamBasic.ts` 纯类型 `StreamPacketBasic` 改 `export type`；
3. `snowcat-test/shims/webui-backend-index.ts`：`pendingTokenToSend` 在 index.ts 是 `export let`，Data.ts 子路径没有它——shim 改为活的 getter/setter 替身 + 同名常量占位。

### 5.5 待窗口项（B 路线）

- 真号登录后跑同一套 selftest（带 token 401/200 双路径、真消息→Milky SSE message_receive 信封断言、OB12 ws 收 message 事件）。
- `injectRawMessage` 落地后，独立模式 + mock 消息源可以做端到端事件注入演练，不依赖真号。
